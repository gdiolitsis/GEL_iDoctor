### Old vs new behavior — explained
The previous `lab1SpeakerTone()` was ~321 physical lines versus ~73 in the new version. Much work was transferred to `AcousticStimulusProbe` and `AcousticEvidenceMath`, not merely deleted. The previous flow played DTMF and then ran a generic microphone analysis **after** playback; that RMS/Peak was not proof that the loudspeaker emitted DTMF. The candidate now captures a pre-tone baseline and live microphone response during DTMF and compares actual frequency-specific rise. This improvement must be preserved.

### Targeted restoration (scoped)
- Reintroduce the useful **raw microphone RMS/Peak** reporting, now from the *synchronized* capture, explicitly marked PCM (not sound pressure level or speaker health).
- Restore safe **retry / disconnect external audio** guidance if inconclusive.
- Fix **false "completed"** text if the attempt was blocked (UNAVAILABLE).
- Restore the old **Bluetooth/wired external-output precaution** in a conservative modern form: inspect *available* output devices, and when an external option exists, block built-in-speaker attribution with UNAVAILABLE/retry (not hardware FAIL). Importantly, available device != measured active route.
- Extract type classification into `AcousticOutputRoutePolicy` for pure unit tests.
- **Do not restore** legacy global AudioManager state forcing (`setSpeakerphoneOn`, SCO toggles, `MODE_NORMAL`, forced unmute), post-tone speaker failure inference, or uncalibrated confidence colors.

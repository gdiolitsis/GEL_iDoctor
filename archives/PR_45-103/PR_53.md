### Verified issues and source changes
- Previous Lab 24 inferred a fake root/security confidence percentage from root binaries, package visibility, `test-keys` and OS boot metadata. Missing paths were effectively treated as evidence that rooting had not occurred.
- Replaced the heuristic score with limited, observable indicators and explicit **UNKNOWN** when the system cannot provide evidence. A visible root manager only indicates package visibility, not working root access.
- New pure Java `Lab24BootEvidence` classifier with **10 unit test cases** checks green/locked, yellow/nonstandard, orange/red or unlocked, contradictory properties and absent/custom OEM properties. Even green/locked is only **OS-reported, not verified attestation**.
- The existing intermediate Lab24 branch had three undefined helper calls. Implemented unprivileged, bounded, allowlisted `getprop` reads, direct file existence checks and targeted package lookups; no hidden API, root commands or broad installed-app inventory.
- Removed invented 0–100 security/risk conclusions; no false "root free", "firmware untouched", "verified boot certified" or OEM authenticity claims.
- **20 independent falsification/device cases** documented at `docs/qa/LAB24_BOOT_INTEGRITY_EVIDENCE_ACCEPTANCE_2026-11-09.md`.

## Original description

## Purpose — research only, no runtime changes

A source-level audit of what the GEL iDoctor diagnostic Labs **actually measure** and what the Android public SDK can legitimately provide. This is deliberately separate from the current v5.3 QA/release candidate (#44).

### Deliverables
- **Lab 14A forensic review:** 16 high-priority issues, 16 falsification/regression test cases, a measured-signal and public-API inventory, safe staged architecture, exact boundaries between charge level, current draw, inferred wear and *actual* battery State of Health. Includes critical findings that confidence and aging functions contain placeholders/uncalibrated rules, possible fabricated 100% SOH and mismatched Lab14→17/30/31 persistence, plus unsafe current unit scaling and lossy signed sysfs parsing.
- **All 31 Labs:** source-observable data, possible additional API measurements, permission/hardware/Play policy limitations, evidence tiers, and a prioritized QA roadmap. Includes newly detected P0 Lab18 NAND-wear false inference, Lab28 keyword-to-symptom false inference and Lab31 stale/false-positive summary risk.

### Grounding
ManualTestsActivity.java, Lab14Engine.java, iDoctorEngine.java, AndroidManifest.xml; verified against official Android SDK BatteryManager, PowerManager, ConnectivityManager, Camera2, SensorManager, BiometricManager, ActivityManager and package-visibility documentation.

### Important nonclaims
These are **code-level findings and research proposals**, not proof of real-device failures or validated enhancements. No binary, permissions, diagnostics behavior, account state, billing, Play release, or app source has changed on this branch.

### Implementation order (separate future PRs)
1. Lab14A fail-closed SoH/confidence/aging/units/data provenance and result schema.
2. Cross-Lab migration/report truthfulness (Labs 17, 28, 30, 31).
3. Safe passive battery/thermal API collector; only then controlled stimulation with abort guards.
4. Functional test expansion and OEM/real-device correlation.

**Do not merge this as a release approval. No main merge or Play rollout without explicit owner authorization.**

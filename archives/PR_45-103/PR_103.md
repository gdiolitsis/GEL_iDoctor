## Real-device evidence (Xiaomi Android 13)
- Labs 1 and 2 first run returned `Media stream muted; no acoustic challenge` and `0/0`, with no tone stimulus.
- Re-run reached confirmation prompts, but titles/messages were invisible (white-on-white standard AlertDialog), while yellow NO/YES/SOME/NONE/ALL 4 buttons were visible.
- Root cause for first run: `AcousticStimulusProbe.run()` rejects `AudioManager.STREAM_MUSIC <= 0` before playback; this is a truthful preflight but lacked user guidance and re-test flow. Not proof of hardware failure.

## Scoped changes
- Replace only the shared `requestSpeakerUserEvidence` UI for Labs 1–2 with existing GEL dark/gold root and header, visible green question, red/white NONE/NO, yellow/black SOME and green/black ALL/YES actions.
- Preserve exactly the user's YES/NO/SOME report semantics; mark negative/partial user reports neutral rather than green.
- Add a readable and localized media-volume==0 preflight before starting either Lab, with explicit user-adjusted volume retry; never change system audio level programmatically.
- Keep `AcousticStimulusProbe`, ToneGenerator, microphone capture, sample timing, DSP analysis and other labs entirely unchanged.

## Acceptance conditions
- Compile and tests; inspect screenshots for both Greek and English, light/dark Android themes.
- Real device: media volume 0 must show instructive prompt without playing tone; increase MEDIA volume and RETRY should run actual sample; cancellation must not create a positive report.
- Ensure 1/1 and 4/4 refer to *recorded* tone samples, not speaker certification; verify the person can actually hear all tones, and handle BT/wired route explicitly.
- Compare previous backup and current probe before any deeper audio-engine changes.

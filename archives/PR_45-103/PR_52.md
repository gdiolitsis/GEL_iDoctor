## 31 Labs Turbo — Lab 21 biometric and screen-lock evidence

**Isolated Draft PR** based on unchanged PR #46 `363dece0aec9c9c032c3cfa1bfbdf7380dbda38e`, independent of other Labs #47–#51. No main merge, Play publication, permissions, account changes or root access additions.

### Verified existing implementation defects
- `BiometricPrompt.onAuthenticationFailed()` (a retryable non-match) was logged as a **terminal hardware FAIL**, allowing a subsequent success to contradict it.
- `onAuthenticationError()` universally claimed fallback to device PIN even for error/cancel/lockout without evidence.
- `BiometricManager.canAuthenticate(int)` (API30+) was called on API29; weak-capable devices were declared ready but prompt required strong.
- `isDeviceSecure()`, foreground unlocked state and root-only filesystem path checks became unsupported security/keystore/post-reboot guarantees and an arbitrary 0–100 score.
- No explicit opt-in gate or single terminal session token.

### Scope-limited implementation
- OS-reported keyguard state and biometric readiness are typed separately, with **UNKNOWN** when unavailable.
- Correct API gating: API30+ STRONG/WEAK matching prompt; API29 no-argument readiness; API28 optional prompt with unknown readiness; below API28 NOT_TESTED.
- User explicitly opts into an Android system BiometricPrompt; no biometric templates stored or disclosed.
- A new `Lab21BiometricEvidence` state machine leaves non-matches IN_PROGRESS until real OS success, user cancellation or terminal error; duplicate/stale callbacks ignored.
- One prompt success = **Android authentication observed**, not proof of a sensor's general hardware health, modality or firmware.
- Removes Lab21 artificial security risk percentages and root file probes. Activity destroy cancels pending biometric prompt; no privileged reading.
- **10 pure-Java unit regressions**, **20 real/emulator negative controls** in `docs/qa/LAB21_BIOMETRIC_EVIDENCE_ACCEPTANCE_2026-11-09.md`.

### Mandatory validation gates
- [ ] Exact current SHA build, Java unit tests and PRO/backend validation.

- [ ] Real Android 9/10/11/16 where available, STRONG/WEAK/enrollment/multi-biometric and mid-prompt cancellation checks.
- [ ] Cross-Lab30/31 report provenance and stale outcomes.
